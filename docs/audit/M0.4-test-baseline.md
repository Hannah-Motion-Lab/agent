# M0.4 — Test baseline & quarantine

> Established 2026-08-18 on the frozen v1.18.18 fork, before and after the
> M0.2 de-branding pass. This is the regression net every later phase relies
> on: if a number here drops, something broke.

## Suites

The fork has four test suites. They **cannot run from the repo root** (guard:
`do-not-run-tests-from-root`); run `bun test` from each package directory.
`scripts/test-ci.sh` does this for CI, skipping anything listed in
`scripts/test-quarantine.txt`.

| Package | Command | Runtime |
| --- | --- | --- |
| `packages/core` | `bun test` | ~40 s |
| `packages/ui` | `bun test src` | <1 s |
| `packages/tui` | `bun test` | ~7 s |
| `packages/agent` | `bun test --timeout 30000` | ~7–15 min |

## Every failure and what it was

All 18 distinct failures across the passes fell into three buckets. **None
was a real defect in engine behavior**; all were fixture/expectation lag from
this fork's renames.

### A. Tests that already expected the new names (fixed by M0.2 source changes)

The earlier structural pass (2026-08-14) had renamed some *test expectations*
without the corresponding source strings, leaving the suite red. M0.2 fixing
the source turned these green with no test edit:

- `Worktree` × 4 + `experimental HttpApi > serves worktree mutations` —
  expected branch prefix `hannah-agent/<name>`; source still produced
  `opencode/<name>`.
- `CloudflareAIGatewayPlugin` — expected `User-Agent: hannah-agent/…`.

### B. Tests asserting values M0.2 deliberately changed (expectations updated)

- Basic-auth default username, in `auth.test.ts`,
  `httpapi-authorization.test.ts`, `httpapi-instance-route-auth.test.ts`,
  `httpapi-sdk.test.ts` → `hannah-agent`.
- `User-Agent` regexes in `xai.test.ts`, `snowflake-cortex.test.ts`,
  `provider-cloudflare-workers-ai.test.ts` → `^hannah-agent/`.
- nvidia header expectations in `provider.test.ts` → `X-Title: hannah-agent`,
  `X-BILLING-INVOKE-ORIGIN: hannah-agent`, and no `HTTP-Referer` (removed).
- Sound pack / notification title in `attention.test.ts`, `tui.test.ts` →
  `hannah-agent.default` / `hannah-agent`.
- Global tmp path in `core/test/global.test.ts` → `$TMPDIR/hannah-agent`.
- Project marker file in `project.test.ts` → `<git-dir>/hannah-agent`.
- `mcp add` output path → `~/.config/hannah-agent/hannah-agent.json`.
- CLI hint in `error.test.ts` → `` `hannah-agent models` ``.
- Theme id / continuation line in `theme.test.ts`, `presentation.test.ts`,
  `app-lifecycle.test.ts`, `config.test.tsx` → `hannah` / `hannah-agent -s`.
- **Two `$schema` tests rewritten, not retargeted**: ADR-0008 removed schema
  injection entirely, so "creates global jsonc config *with schema*" became
  "creates an empty global jsonc config", and the env-substitution test now
  asserts the loader never writes `$schema` into a user's file.
- Snapshots regenerated deliberately (`help-snapshots`, `inline-tool-wrap`):
  the diffs were the new wordmark, the `hannah-agent` command names, and
  column shifts from longer `HANNAH_AGENT_*` env names. Each diff was read
  before accepting.

### C. Pre-existing fork bugs the earlier rename introduced (real fixes)

These were failing before M0.2 and are now fixed at the root:

- `tool.registry > preserves Zod arg descriptions…` — the test built a fake
  package at `node_modules/@opencode-ai/plugin` whose `package.json` declared
  `name: "@hannah/plugin"`; Node resolves by *directory*, so the import failed.
  Directory renamed to `node_modules/@hannah/plugin`.
- `session.list > filters by path…` and
  `session HttpApi > uses project-scoped path…` — fixtures created sessions
  under `packages/opencode/src` while the query string had been rewritten to
  `packages/agent/src`, so the filter matched nothing. Fixture paths aligned.
- `HttpApi SDK > routes configured SDK directory…` — asserted the fuzzy file
  search returned *exactly* `[hello.txt]`; the renamed `hannah-agent.json`
  now also scores against the query `hello`. Changed to a `toContainEqual`
  assertion, since the test's subject is directory/workspace routing.
- `diff viewer file tree utilities`, `app.exit epilogue`,
  `resolves host-neutral defaults` (tui) — same class: fixture strings left
  behind by the `packages/opencode` → `packages/agent` move.

## Known load-sensitive test

`run-process.test.ts > exits nonzero promptly when the model is unknown` spawns
a CLI subprocess with a 15 s budget and asserts `durationMs < 15_000`. Under a
fully parallel suite on a busy machine it has been observed at 15.2 s — a
failure of the machine, not the code (isolated it runs in ~4.4 s, and a clean
re-run of the whole suite passes). If it fails in CI, re-run before
investigating; if it becomes frequent, raise its budget rather than quarantining
it — the behavior it guards (fail fast on an unknown model) is worth keeping.

## Guarding the net

- CI (`.github/workflows/ci.yml`) runs `bun turbo typecheck` and
  `scripts/test-ci.sh` on push to `main` and on every PR.
- Because the agent suite takes 7–15 minutes, run it before any merge that
  touches config loading, permissions, sessions, or a mechanical rename —
  the three areas where every regression so far has appeared.
- Snapshot updates require reading the diff. A rename that shifts help-text
  columns looks identical in kind to a real regression in output.
