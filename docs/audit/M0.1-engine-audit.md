# M0.1 — Engine audit report

> Executed 2026-08-18 against the frozen v1.18.18 snapshot. Every claim below
> was read from source (file:line) or verified by running the engine. This
> report resolves all **[VERIFY]** markers that were in ARCHITECTURE.md and
> feeds ADR closure (M0.5). Corrections to prior assumptions are marked
> **⚠ CORRECTION**.

## 1. Route table & OpenAPI reference

- Regenerated the spec from source (`hannah-agent generate`): **188 routes**.
  The committed reference is `packages/sdk/openapi.json` — verified
  route-for-route identical to the generated output (no drift).
- The wire surface has **two coexisting generations**, both served by the same
  process and backed by the *same* in-process services:
  - **Legacy** paths: `/session`, `/event`, `/permission`, `/question`,
    `/config`, `/file`, `/find`, `/tui`, `/mcp`, `/vcs`, `/pty`, … (operation
    ids like `session.prompt`).
  - **v2** paths under `/api/*` (operation ids `v2.*`), plus `/global/*`
    (cross-instance) and `/experimental/*`.
- **⚠ CORRECTION** to the original v1↔v2 mental model: the "v1 server" is
  itself built on Effect HttpApi (`server/server.ts` →
  `server/routes/instance/httpapi/{api,server,public}.ts`, groups + handlers
  per resource). The v1/v2 split is real in the *runtime services*, not in the
  HTTP framework.
- **The shipping TUI drives the v2 surface**: `packages/tui/src/context/sdk.tsx:1`
  imports `@hannah/sdk/v2` → `/api/*` routes. Both surfaces call the same
  services (`Permission.Service`, `Question.Service`, prompt service, event
  bridge), so the battle-tested path is those **services**, which is exactly
  where the Hannah façade binds (in-process, ADR-0006). Route choice on the
  wire is irrelevant to the façade.
- Serve defaults (`cli/network.ts`): hostname `127.0.0.1`, port `0` → tries
  **4096** first, then any free port (`server.ts:117`). CORS allowlist empty.
- Instance model: `serve` starts with no ambient project; **each request
  selects its project instance via the `x-opencode-directory` header**
  (`cli/cmd/serve.ts:10`, `@hannah/server/location`). SDK clients send it.
  (Header renamed in M0.2 — see DEBRANDING.)
- Auth: **HTTP Basic**, env-driven (`server/auth.ts`):
  `HANNAH_AGENT_SERVER_PASSWORD` (unset ⇒ *unsecured*, serve prints a
  warning), username `HANNAH_AGENT_SERVER_USERNAME` (default `opencode`,
  renamed in M0.2). No token/bearer mechanism in the engine; the façade's
  bearer token (INTEGRATION §2) is façade-implemented.

## 2. Event catalog

- All state changes publish typed events through `EventV2Bridge` /
  `GlobalBus`; the manifest is assembled in
  `packages/schema/src/event-manifest.ts` from per-domain definition files.
- **89 event types** at `EventManifest.Latest` (extracted from the generated
  spec's `Event` union). Families:
  - `session.next.*` — **33 fine-grained streaming events** (the narration
    goldmine): `text.delta/started/ended`, `reasoning.*`, `tool.called/
    input.*/progress/success/failed`, `step.started/ended/failed`,
    `prompted/prompt.admitted`, `retried`, `compaction.*`, `shell.*`,
    `revert.*`, `model.switched`, `agent.switched`, `moved`, `synthetic`,
    `context.updated`.
  - Lifecycle: `session.created/updated/deleted/idle/error/status/diff/compacted`.
  - Approvals: `permission.asked/replied` (+ `permission.v2.*`),
    `question.asked/replied/rejected` (+ `question.v2.*`).
  - Plan/progress: `todo.updated`; messages: `message.updated/removed`,
    `message.part.updated/delta/removed`.
  - Infra (mostly ignorable for Hannah): `file.edited`, `file.watcher.updated`,
    `lsp.updated`, `mcp.*`, `pty.*`, `tui.*`, `vcs.branch.updated`,
    `workspace.*`, `worktree.*`, `installation.*`, `models-dev.refreshed`,
    `catalog.updated`, `server.connected/instance.disposed`,
    `project.*`, `plugin.added`, `command.executed`, `reference.updated`,
    `integration.*`, `global.disposed`.
- The façade's `hannah.v0` translation map (INTEGRATION §3) is fully coverable:
  task.plan ← `todo.updated`; task.progress ← `session.next.step.*` +
  `session.next.text.*`; task.tool ← `session.next.tool.*`;
  approval.requested ← `permission.asked`; question ← `question.asked`;
  completed/failed ← `session.idle` / `session.error` + prompt exit.

## 3. SSE transport facts

(`server/routes/instance/httpapi/handlers/event.ts`)

- `GET /event` (and `/api/event`, `/global/event`): live tap of the event
  bus — subscribes an unbounded queue at request time, first emits
  `server.connected`, then filtered live events (per-instance directory
  filter), plus `server.heartbeat` every 10 s. Stream ends with
  `server.instance.disposed`.
- **No replay**: the SSE `id:` field is not set (`eventData()` sends
  `id: undefined`) and **no `Last-Event-ID` handling exists anywhere** in the
  server (verified by grep). The `sync/*` routes are a different mechanism
  (client-initiated replay of durable events for cross-device sync), not an
  SSE resume.
- **Consequence (binding for M1.3)**: the façade owns event durability — it
  assigns `seq`, keeps a per-task ring buffer, and implements the
  `Last-Event-ID` resume promised by INTEGRATION §3 itself. The engine
  guarantees only "no gaps while connected".

## 4. Permission system

(`permission/index.ts`, `@hannah/core/v1/config/permission`, `permission/arity.ts`)

- Config shape (`permission` key, global or per-agent): either a single action
  or `{ <permission>: action | { <pattern>: action } }`. Known keys: `read`,
  `edit`, `glob`, `grep`, `list`, `bash`, `task`, `external_directory`,
  `todowrite`, `question`, `webfetch`, `websearch`, `lsp`, `doom_loop`,
  `skill` — plus arbitrary keys (MCP tools, code-mode). `~`/`$HOME` expand in
  patterns. **User key order is precedence; last match wins**; unmatched ⇒
  **`ask`** (`evaluate()`, `permission/index.ts:28`).
- Env override exists: `HANNAH_AGENT_PERMISSION` (JSON ruleset) — useful for
  the Hannah profile.
- Tool → permission mapping: `write`/`edit`/`apply_patch` → `edit`; `read`,
  `glob`, `grep`, `lsp`, `skill`, `todowrite`, `webfetch`, `websearch` →
  same-named; shell → **`bash`** with patterns = arity-derived command
  prefixes (`git status`, `npm install`, `rm`, …; LLM-curated arity table in
  `permission/arity.ts`), and additionally `external_directory` asks with
  directory globs when a command touches paths outside the project. Subagent
  spawn asks `task` with pattern = subagent type.
- **Granularity verdict for ADR-0010: sufficient.** The preset matrices in
  SECURITY §4 are directly expressible as engine rulesets (per-command bash
  safe-list included); the hard-policy layer still wraps them for the
  sensitive-path denylist (patterns are per-command, not per-file-path, for
  bash).
- Ask flow: `ask` publishes `permission.asked` and **blocks on a Deferred**.
  Reply via `POST /permission/{requestID}/reply` (or session-scoped/v2
  variants) with `once` / `always` / `reject` (+ optional feedback message →
  "corrected" error the model sees). `always` appends allow-rules to
  **in-memory** instance state (not persisted). `reject` also **cascades**:
  rejects all other pending asks of the same session.
- **No engine timeout on asks** — pending asks live until replied or the
  instance disposes (finalizer rejects them). SECURITY's "timeout ⇒ deny
  (120 s)" is **façade-implemented** (M1.3), not engine config.

## 5. `question` tool round-trip

(`tool/question.ts`, `question/index.ts`)

- Tool asks with a list of prompts (multi-question, options + free text);
  service publishes `question.asked`, blocks on a Deferred.
- Reply: `POST /question/{requestID}/reply` with `answers: string[][]`;
  reject: `POST /question/{requestID}/reject` → tool receives RejectedError
  ("user dismissed"). List pending: `GET /question`. Events:
  `question.replied` / `question.rejected`.
- Same no-timeout semantics as permissions. Maps 1:1 onto `hannah.v0`
  `question`/`answered` events; voice answers POST the reply.

## 6. Abort semantics

- `POST /session/{sessionID}/abort` → `promptSvc.cancel(sessionID)`
  (`handlers/session.ts:232`), returns `true`. Cancels the in-flight prompt
  run (fiber interruption); **the session and its history survive**; a new
  prompt can be sent afterwards. Repeat aborts are safe (cancel of an idle
  session is a no-op). Pending permission/question asks die with the
  interrupted run's scope.
- `prompt_async` (`handlers/session.ts:311`) = fire-and-forget prompt: forks
  the run, errors surface as logs + `session.error` events. This is the
  natural engine call under the façade's `POST /hannah/v0/tasks`.

## 7. Storage

- **Global paths** (`packages/core/src/global.ts`): single constant
  `app = "opencode"` → `~/.local/share/opencode` (data), `~/.cache/opencode`,
  `~/.config/opencode`, `~/.local/state/opencode`, `$TMPDIR/opencode`.
  Subdirs: `data/log`, `data/repos`, `cache/bin`. `HANNAH_AGENT_CONFIG_DIR`
  overrides config dir; `HANNAH_AGENT_TEST_HOME` overrides home. (All renamed
  in M0.2 — one-constant choke point.)
- **SQLite** (`core/src/database/database.ts:43`): default
  `<data>/opencode.db` on release channels, `<data>/opencode-<channel>.db`
  otherwise (source runs are channel `local` ⇒ `opencode-local.db`; verified
  live). Override: `HANNAH_AGENT_DB` (absolute path or `:memory:`). WAL mode.
  Holds the v2-stack tables (credentials, account, control-plane/workspace,
  migrations).
- **v1 JSON store** (`packages/agent/src/storage/storage.ts`): session info /
  messages / parts as JSON files under `<data>/storage/session/{info,message,part}/…`
  — this is where session content actually persists on the v1 path.
  Purge = delete session via API or remove files; retention policy is ours to
  build (P3).
- Boot behavior (verified live, scratch `$HOME`): creates all dirs above plus
  a template `~/.config/opencode/opencode.jsonc`; offline no-key boot is
  healthy: `GET /global/health` → `{"healthy":true,"version":"local"}`.

## 10. Subagents (`task` tool)

(`tool/task.ts:100-180`)

- Depth limit: config `subagent_depth`, **default 1** (subagents cannot spawn
  subagents unless raised).
- Spawn requires a `task` permission ask (pattern = subagent type) unless the
  agent config pre-allows it.
- Child session inherits a derived ruleset; `todowrite` and recursive `task`
  are denied for the child unless its agent definition allows them.
- Background subagents are gated behind
  `HANNAH_AGENT_EXPERIMENTAL_BACKGROUND_SUBAGENTS=true`.
- Cost control = the parent's timebox/abort (façade-level); no engine budget.

## 12. Façade seams (what M1.3 builds against)

| Need | Engine seam |
| --- | --- |
| Create/drive a task | `Session` create + `prompt_async`-equivalent service call (in-process), or the same services the `/api/session` handlers use |
| Events | `EventV2Bridge.Service` subscription (same tap the SSE handlers use) — translate to `hannah.v0`, assign `seq`, buffer for resume |
| Approvals | `Permission.Service.{list,reply}` + `permission.asked` events; timeout policy implemented here |
| Questions | `Question.Service.{list,reply,reject}` + events |
| Cancel | prompt service `cancel(sessionID)` |
| Permission presets | per-session `permission` ruleset at session create (session records carry a `permission` field) + `HANNAH_AGENT_PERMISSION` baseline |
| Auth | Basic auth is engine-level; the façade adds its own bearer check on `/hannah/v0/*` |
